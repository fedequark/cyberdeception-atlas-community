# Public repository strategy

**Decision prepared, not executed (2 October 2026).** Keep `fedequark/cyberdeception-atlas` private as the operational repository while its Git history and weekly D1 backups contain material that has not been cleared for public redistribution. A separate public repository can start from one new clean commit containing only an audited allowlist. Do not change the visibility of the operational repository or push its history to the public destination.

The clean mirror must exclude `backups/`, the backup workflow, local/private artifacts, pending submissions, operational revision and monitoring tables, credential files, review source texts whose redistribution rights are unresolved, and archived local packages not needed to build the site. A file being tracked or already referenced in a paper does not by itself establish redistribution rights. The public mirror's source manifest must list included paths, SHA-256 hashes and source commit, and its creation script must fail on any unexpected file. Rescan the staged bytes for secret patterns and personally identifiable or operational data; a negative pattern scan is only one check.

The private repository remains the production deployment source and D1 remains the single published catalog. Public issues and pull requests are proposals. A maintainer imports an accepted patch into the private source with attribution and links the decision; releases are then synchronized to the public mirror. This is a transitional route, because maintaining two code repositories needs a documented sync check. If a later full history audit and private backup migration make the operational repository safe to expose, the owner can reconsider this design. Do not claim the mirror preserves the original Git history.

Before launch: establish a verified private security-report channel; decide who maintains the mirror and who can review; verify code, data and third-party rights; build and test the exact allowlisted tree; compare its hashes and URLs; create the destination; obtain owner approval of the exact payload. The public repository may describe itself as open to proposals only once the intake and response path works. It may describe external collaboration only after real contributors participate.
